# IRIS v2 — минимальное ядро

Поддерживается Python 3.10.

## Установка

```powershell
python -m pip install -r requirements.txt
python -m pip install -e . --no-deps
```

Первая команда устанавливает зависимости, вторая подключает сам проект в
режиме разработки без повторной загрузки пакетов.

## Создание проекта

```powershell
iris-v2 create "D:\IRIS_projects\Test" `
  --name "Тестовый проект" `
  --code "TEST-001" `
  --organization "АО Пример" `
  --opo "Тестовый ОПО" `
  --registration-number "А00-00000-0000"
```

## Открытие проекта

```powershell
iris-v2 open "D:\IRIS_projects\Test"
```

Папка проекта содержит `project.sqlite3`, `project.json`, `input` и `output`.

## Данные проекта

После создания или открытия проекта нажмите кнопку **Данные проекта**. В форме
заполняются название и шифры разделов, а также сведения о разработчике.

Модуль самостоятельно создаёт и редактирует файл в папке проекта:

```text
project_common.json
```

Файл не зависит от SQLite и расчётных модулей. Неизвестные дополнительные поля
при редактировании сохраняются.

### Постоянные разработчики

Каждый разработчик хранится в отдельном файле:

```text
developers/
├─ Ecopromproject/developer.json
└─ Другой разработчик/developer.json
```

За основу можно взять обезличенный пример:

```powershell
New-Item -ItemType Directory .\developers\Example
Copy-Item .\src\iris_v2\data\developer.json `
  .\developers\Example\developer.json
```

После перезапуска программы разработчики появятся в выпадающем списке формы
**Данные проекта**. При выборе все сведения подставляются автоматически, но их
можно изменить для конкретного проекта.

## Окно программы

```powershell
python main.py
```

Также окно можно запустить командой `iris-v2-gui`.

## Организации и ОПО

Для каждой организации создайте отдельную папку и скопируйте в неё справочник:

```powershell
New-Item -ItemType Directory .\organizations\Example
Copy-Item .\src\iris_v2\data\organization.json `
  .\organizations\Example\organization.json
```

Структура справочников:

```text
organizations/
├─ Orenburgneft/organization.json
├─ Tatneft/organization.json
└─ Другие организации/organization.json
```

Программа автоматически загружает все файлы `organizations/*/organization.json`.
В каждом файле используется исходная вложенная структура: сведения об
организации находятся в `organization`, а список её ОПО — в `sites`.
После изменения файлов перезапустите программу.

Папка `organizations` исключена из Git. Если в ней нет справочников, программа использует
обезличенный пример `src/iris_v2/data/organization.json`.

При создании проекта в его базу копируются все разделы организации и все поля
выбранного ОПО без распрямления. Список остальных ОПО в снимок не попадает.

Значение `sanitary_protection_zone_m: 0` означает, что санитарно-защитная
зона у ОПО отсутствует. `employees_other_opo_count` — суммарная численность
людей на соседних ОПО в возможной зоне воздействия.

## Вещества

Архив веществ хранится независимо от проектов:

```text
substances/
└─ archive/
   ├─ DNS_UPSV/*.json
   ├─ NPZ/*.json
   └─ другие группы/*.json
```

После открытия проекта нажмите **Вещества**, найдите и отметьте нужные позиции,
затем нажмите **Сохранить**. В папке проекта будет создан `substances.json`.

Одновременно создаётся `info.txt` с колонками `id`, `name`, `kind`. Его можно
открыть в Excel или использовать как памятку при заполнении ID веществ.

Проектные ID назначаются последовательно от 1 в порядке таблицы. Исходные файлы
архива не изменяются. Промежуточная папка `active` и скрипт
`make_active_substances.py` не требуются.

## Оборудование

Сначала сохраните вещества проекта. При первом нажатии **Оборудование** программа
создаст новый шаблон:

```text
<проект>/input/equipment_data.xlsx
```

Заполните лист `Equipment Data`, сохраните файл и повторно нажмите
**Оборудование**. Если файл уже существует, программа предложит:

- импортировать существующий файл;
- создать новый шаблон с типовым заполнением;
- отменить действие.

Создание нового шаблона требует отдельного подтверждения и полностью заменяет
старый `input/equipment_data.xlsx`. Новый файл сначала формируется во временном
файле, поэтому ошибка создания не повредит существующий Excel.

При успешной проверке создаётся
`<проект>/equipments.json`. Повторный импорт полностью заменяет прежний файл.
Шаблон формируется по выбранным веществам. Для каждого `substance_id` создаётся
по одной строке каждого типа оборудования, разрешённого справочником типовых
сценариев для его `kind`. Невозможные сочетания в Excel не добавляются.
Типовые строки можно изменить, скопировать или удалить.
`pressure_mpa` должен быть не меньше `0.1`. Координаты вводятся одним полем
`coordinates` в формате `[0, 0]` или `[0, 0, ...]`. `coord_type`: `0` —
линейный, `1` — стационарный, `2` — другое.

В формате v2 старое поле `quantity_equipment` разделено:

- `total_length_m` — полная длина трубопровода для частоты;
- `equipment_count` — количество единиц оборудования для частоты;
- `accident_section_length_m` — длина отключаемого аварийного участка.

ID вещества проверяется по `substances.json`. Составляющие ОПО формируются из
`hazard_component`. Ошибки не исправляются автоматически: импорт блокируется,
а подробный протокол записывается в `equipment_import_errors.txt`.

Для одновременного расчёта стандартной частоты, варианта без компенсирующих
мероприятий и варианта с ними используйте разные значения `hazard_component`:

```text
Участок трубопроводов
Участок трубопроводов (без КМ)
Участок трубопроводов (с КМ)
```

Отметка `(без КМ)` или `(с КМ)` должна находиться в конце названия.

## Расчёт количества опасного вещества

После импорта оборудования нажмите **Количество ОВ**. Программа независимо
читает `substances.json` и `equipments.json`, затем создаёт
`<проект>/amount_results.json`.

Для трубопровода внутренний объём рассчитывается по длине аварийного участка:

```text
Dвн = diameter_mm - 2 × wall_thickness_mm
V = π × Dвн² / 4 × accident_section_length_m
```

Для газа используется `density_gas_kg_per_m3`, для жидкости —
`density_liquid_kg_per_m3`. В аппаратах с жидкой средой отдельно учитываются
жидкая и газовая части объёма по `fill_fraction`. Для насоса и жидкостного
трубопровода весь расчётный объём принимается заполненным жидкостью — как в
старой программе.

`amount_t` — количество вещества в одной единице оборудования перед аварией.
`equipment_count` его не увеличивает: это поле используется только при расчёте
частоты. Сценарную массу выброса программа рассчитает следующим отдельным
модулем с учётом разгерметизации и времени отключения.

## Формирование расчётных сценариев

После импорта оборудования нажмите **Расчётные сценарии**. Программа независимо
читает `substances.json`, `equipments.json`, `typical_scenarios.json` и
`calculation_config.json`, затем создаёт:

```text
<проект>/calculation_cases.json
```

Для каждой строки оборудования выбираются сценарии по сочетанию
`equipment_type × kind`. Им присваиваются сквозные коды `С1`, `С2`, ... в
порядке оборудования и строк типового справочника. В файл также записываются
вещество, составляющая ОПО, вид расчёта, режим частоты и множитель КМ.

`unit_scenario_frequency` — типовая удельная частота сценария. На этом этапе она
не умножается на длину трубопровода, количество оборудования или множитель КМ:
это выполняет отдельный модуль расчёта частоты.

## Расчёт частот

После формирования сценариев нажмите **Расчёт частот**. Программа читает
`calculation_cases.json` и создаёт `<проект>/frequency_results.json`.

Сохранена формула старой программы:

```text
scenario_frequency = unit_scenario_frequency
                     × frequency_basis
                     × frequency_multiplier
```

Для трубопроводов `frequency_basis` — `total_length_m` в метрах, для остальных
типов — `equipment_count` в штуках. Пересчёта метров в километры нет, как и в
старом IRIS. Коэффициенты стандартного расчёта, без КМ и с КМ берутся из
`calculation_config.json`. Результат содержит частоту каждого сценария и
суммарную частоту по проекту в `1/год`.

## Расчёт массы вещества в аварии

Сначала выполните **Количество ОВ** и **Расчётные сценарии**, затем нажмите
**Масса в аварии**. Независимый модуль читает:

```text
equipments.json
substances.json
amount_results.json
calculation_cases.json
calculation_config.json
```

и создаёт `<проект>/release_results.json`. Для каждого сценария сохраняются
запас вещества `amount_t`, вышедшая часть запаса `inventory_release_t`, режим
выброса, массовый расход `flow_kg_s`, масса притока за время отключения
`flow_mass_t` и итоговая масса в аварии `ov_in_accident_t`.

Сохранены формулы и правила старого IRIS:

- трубопровод с жидкостью — масса отключаемого участка плюс приток через
  сечение трубопровода; для частичной разгерметизации применяется
  `partial_release_fraction`;
- газовое оборудование — масса внутри оборудования плюс критическое истечение
  газа через заданное отверстие за `shutdown_time_s`;
- аппарат с жидкой и газовой фазами — при полном разрушении выходит весь запас,
  при частичном разрушении считается истечение ниже или выше уровня жидкости;
- насос — запас в насосе плюс истечение жидкости через заданное отверстие;
- резервуар и цистерна без давления — полный запас или его заданная доля.

Диаметры отверстий и доля частичной разгерметизации берутся из
`calculation_config.json`. Давление `pressure_mpa` используется как абсолютное,
как в исходной формуле старой программы. Ошибка старого модуля цистерны под
давлением для `kind=0`, где строки 7 и 8 оставались без массы, устранена: для
них рассчитывается истечение из газовой фазы согласно тексту сценария.

## Расчёт площади пролива

После расчёта массы нажмите **Площадь пролива**. Модуль читает
`release_results.json`, `equipments.json`, `substances.json` и
`calculation_config.json`, затем создаёт `<проект>/spill_results.json`.

Если `spill_area_m2` не задан или равен нулю, применяется формула старого IRIS:

```text
spill_area_m2 = ov_in_accident_t × spill_coefficient
```

Если площадь задана вручную, для полного пролива она используется без
изменений, а для частичного умножается на `partial_spill_fraction`. При
автоматическом расчёте дополнительное уменьшение площади не выполняется:
частичная масса уже учтена в `ov_in_accident_t`.

Применимость определяется по режиму выброса. Для истечения газа из газовой
фазы площадь имеет значение `null`; жидкостные выбросы трубопроводов,
резервуаров, аппаратов и насосов рассчитываются. Нулевой коэффициент при
незаданной площади считается ошибкой, а не даёт молча нулевой результат.

## Расчёт испарившейся массы

После расчёта площади пролива нажмите **Испарение**. Независимый модуль читает
`spill_results.json`, `equipments.json`, `substances.json` и
`calculation_config.json`, затем создаёт `<проект>/evaporation_results.json`.

Сохранены формулы старого IRIS. Давление насыщенного пара определяется по
температуре вещества:

```text
Pнас = 101325 × exp[-(L × M / R) × (1 / T - 1 / Tкип)]
W = 10⁻⁶ × η × Pнас[кПа] × √M[г/моль]
mисп = min(W × Sпролива × tисп / 1000, mаварии)
```

В настройках расчёта коэффициент испарения `η` по умолчанию равен `1,0`.
Итоговая масса не может превышать массу вещества в аварии. Обычная модель
испарения применяется к видам вещества `0`, `1` и `8`, как в старых расчётных
модулях. Для чистых газов, СУГ и практически неиспаряемых жидкостей результат
имеет статус «модель не применяется»; для газового выброса — «пролив
отсутствует». Такие сценарии не удаляются из итогового файла.

## Масса вещества в поражающем факторе

После расчёта испарения нажмите **Масса ПФ**. Модуль читает
`evaporation_results.json` и `calculation_config.json`, затем создаёт
`<проект>/hazard_factor_results.json`.

Источник расчётной массы выбирается по `calc_code`: для пожара пролива,
факельного горения и химически опасного пролива используется вся масса в
аварии; для взрыва — доля сформировавшегося облака; для пожара-вспышки —
испарившаяся масса либо газовая масса; для токсического поражения — вся
испарившаяся или вышедшая масса; для огненного шара — масса с учётом доли
BLEVE. Для ликвидации аварии масса поражающего фактора равна нулю.

В каждой строке сохраняются источник и формула, `ov_in_hazard_factor_t`, а для
факельного горения также `hazard_factor_flow_kg_s`. Доли облака и BLEVE берутся
из `calculation_config.json`.

## Пожар пролива

После расчёта массы поражающего фактора нажмите **Пожар пролива**. Модуль читает
`hazard_factor_results.json`, `substances.json` и `calculation_config.json`,
затем создаёт `<проект>/pool_fire_results.json`.

Для сценариев с `calc_code = 1` рассчитываются радиусы теплового воздействия
`q_10_5_m`, `q_7_0_m`, `q_4_2_m`, `q_1_4_m` для интенсивностей 10,5; 7,0;
4,2 и 1,4 кВт/м². Используются площадь пролива, скорость ветра, температура
кипения, молярная масса и индивидуальная скорость выгорания вещества
`burning_rate_kg_per_s_m2`.

Расчётная модель перенесена из старого `_strait_fire.py`. Исправлена размерность
молярной массы: проект хранит кг/моль, а формула плотности пара использует
кг/кмоль. Медленный перебор расстояния шагом 0,1 м заменён поиском границы зоны
с точностью 0,1 м. Сценарии других типов сохраняются с пустыми радиусами и
статусом «не применяется».

## Взрыв облака ТВС

После расчёта массы поражающего фактора нажмите **Взрыв ТВС**. Модуль читает
`hazard_factor_results.json`, `equipments.json` и `substances.json`, затем
создаёт `<проект>/explosion_results.json`.

Для сценариев с `calc_code = 2` рассчитываются радиусы действия избыточного
давления 100, 70, 28, 14, 5 и 2 кПа. Из оборудования используется степень
загромождённости `clutter_degree`, а из раздела `explosion` вещества —
`explosion_hazard_class`, `heat_of_combustion_kJ_per_kg`, `expansion_degree`
и `energy_reserve_factor`. Масса облака берётся из
`ov_in_hazard_factor_t`.

Формулы перенесены из старого `_tvs_explosion.py`. Исправлена граница `p_2`:
старый модуль фактически искал 3,5 кПа, новый рассчитывает указанные 2 кПа.
Перебор радиуса шагом 0,5 м заменён поиском границы с точностью 0,1 м.
Сценарии других типов остаются в итоговом файле со статусом «не применяется».

## Пожар-вспышка

После расчёта массы поражающего фактора нажмите **Пожар-вспышка**. Модуль
читает `hazard_factor_results.json` и `substances.json`, затем создаёт
`<проект>/flash_fire_results.json`.

Для сценариев с `calc_code = 3` рассчитываются радиус достижения НКПР
`lel_radius_m` и радиус пожара-вспышки `flash_fire_radius_m`. Используются
масса `ov_in_hazard_factor_t`, молярная масса `molar_mass_kg_per_mol`,
температура кипения `boiling_point_C` и НКПР `lel_percent`.

Модель перенесена из старого `_lower_concentration.py`: радиус пожара-вспышки
равен `1,2 × R НКПР`. Для газов видов `2`, `3` и `7` используется готовая
`density_gas_kg_per_m3`; температура кипения им не требуется. Для паров
жидкости плотность рассчитывается по молярной массе и температуре кипения.
Молярная масса переводится из кг/моль в кг/кмоль. Сценарии других типов
сохраняются с пустыми радиусами и статусом «не применяется».

## Факельное горение

После расчёта массы поражающего фактора нажмите **Факельное горение**. Модуль
читает `hazard_factor_results.json` и создаёт
`<проект>/jet_fire_results.json` для сценариев с `calc_code = 5`.

По расходу `hazard_factor_flow_kg_s` рассчитываются длина и диаметр факела.
Тип факела выбирается по виду вещества и режиму истечения: газовый, газовый
факел СУГ либо жидкостный факел/факел СУГ. Формулы и коэффициенты перенесены
из старого `_jet_fire.py` (формулы П3.71–П3.72 Приказа МЧС № 404).
Сценарии других типов сохраняются со статусом «не применяется».

## Токсическое поражение — временная оценка

После расчёта массы поражающего фактора нажмите **Токсическое поражение**.
Для сценариев с `calc_code = 4` создаётся `<проект>/toxic_results.json`.

Временно перенесена формула старого `_toxi_fake.py`: `Rсмерт = 5 × m^0,33`,
`Rпорог = 15 × m^0,33`, где масса `m` задаётся в килограммах, зоны получаются
в метрах. Коэффициенты произвольные: это не модель рассеивания и не
нормативный расчёт. В окне и JSON результат явно помечается как временный.

## Огненный шар

После расчёта массы поражающего фактора нажмите **Огненный шар**. Модуль читает
`hazard_factor_results.json` и `calculation_config.json`, затем создаёт
`<проект>/fireball_results.json` для сценариев с `calc_code = 6`.

Рассчитываются эффективный диаметр, высота центра, время существования
огненного шара и радиусы тепловых доз 600, 320, 220 и 120 кДж/м². Формулы
перенесены из старого `_fireball.py`. Перебор расстояния шагом 0,5 м заменён
поиском границы с точностью 0,1 м.

Средняя поверхностная плотность теплового излучения задаётся параметром
`fireball_surface_emissive_power_kw_m2`. Значение по умолчанию 350 кВт/м²
перенесено из старого `config.py`.

## Химически опасный пролив

После расчёта массы поражающего фактора нажмите **Химически опасный пролив**.
Модуль читает `hazard_factor_results.json` и создаёт
`<проект>/chemical_spill_results.json` для сценариев с `calc_code = 7`.

Для практически неиспаряемой токсичной жидкости (`kind = 6`) сохраняется
рассчитанная ранее площадь `spill_area_m2`. Искусственные радиусы облака или
токсического поражения не создаются. Остальные сценарии сохраняются со
статусом «не применяется».

Кнопки расчётов поражающих факторов вынесены в отдельную строку главного окна,
чтобы они не обрезались при добавлении новых модулей.

## Свод зон поражения

После выполнения нужных расчётов нажмите **Свод зон**. Модуль читает
`hazard_factor_results.json` и только те файлы результатов, которые требуются
фактически присутствующим `calc_code`, затем создаёт
`<проект>/impact_zones.json`.

В одной таблице собираются зоны пожара пролива, взрыва ТВС, пожара-вспышки,
размеры факела, зоны огненного шара и площадь химически опасного пролива.
Для `calc_code = 0` указывается отсутствие поражающего фактора. Результаты
токсического поражения (`calc_code = 4`) включаются в свод со статусом
«Временная оценка по массе».

## Число погибших и пострадавших

После формирования свода зон нажмите **Погибшие и пострадавшие**. Модуль
читает `impact_zones.json` и значения `possible_dead`, `possible_injured` из
`equipments.json`, затем создаёт `<проект>/people_results.json`.

Правила перенесены из старого `_calc_people.py` и сведены к компактной
функции по типу оборудования, виду вещества, строке сценария и поражающему
фактору. Сохранены результаты всех 308 ранее обработанных сочетаний. Для 62
сочетаний, где старая функция возвращала `None`, добавлены правила по
аналогичным типам оборудования. Для каждого сценария сохраняется код
применённого правила; отдельно выводятся максимальные числа погибших и
пострадавших среди сценариев.

## Расчёт ущерба

После расчёта погибших и пострадавших нажмите **Ущерб**. Модуль читает
`people_results.json` и `calculation_config.json`, затем создаёт
`<проект>/damage_results.json`. Все результаты сохраняются в тыс. руб.

Из старой программы перенесены кусочно-линейная оценка базовой стоимости,
наборы коэффициентов для 1, 2, 6, 8 и 9 сценариев, доли затрат на ликвидацию
и экологического ущерба, а также расчёт социальных и косвенных потерь.
Масштабирование задаётся существующим параметром `damage_scale` в окне
**Настройки расчёта**. В таблице выводятся все составляющие и суммарный ущерб.

## Типовые сценарии аварий

Кнопка **Типовые сценарии** доступна без открытия проекта. Окно показывает
сценарии для выбранного сочетания `equipment_type × kind`: текст, базовую
частоту, вероятность события, частоту сценария и код расчёта. Справочник
доступен только для чтения — расчётные данные из него не изменяются формой.

Встроенный справочник находится в
`src/iris_v2/data/typical_scenarios.json`. Чтобы использовать собственную
версию без изменения программы, поместите полный файл по пути:

```text
typical_scenarios/typical_scenarios.json
```

При загрузке проверяются все 100 сочетаний типов оборудования и видов веществ,
формулы частот и обязательные поля. Текущий справочник содержит 62 разрешённых
сочетания, 38 явных запретов и 370 сценариев.

## Настройки расчёта

Кнопка **Настройки расчёта** открывает независимую форму параметров. После
сохранения в корне проекта создаётся `calculation_config.json`. В нём хранятся
доли частичной разгерметизации, облака, BLEVE и пролива, скорость ветра,
диаметры отверстий истечения, масштаб ущерба и множители частоты. Стандартный
множитель всегда равен `1,0`; значения по умолчанию взяты из старого `config.py`.

## Проверка исходных данных

После заполнения проекта нажмите **Проверка данных**. Независимый модуль проверяет
организацию и ОПО, `project_common.json`, `substances.json` и `equipments.json`,
включая связи оборудования с веществами и параметры оборудования. Зелёные строки
означают, что раздел готов; красные содержат все найденные ошибки. Для выбранной
строки можно открыть соответствующий файл или папку. Расчёт допускается только
после успешного прохождения всех шести разделов. Отдельно проверяется, что для
каждой строки оборудования существует допустимая пара `equipment_type × kind`
и соответствующий набор типовых сценариев.
